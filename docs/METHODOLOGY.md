## 2. Как искали ошибки (три независимых слоя)

**Слой A — детерминированные правила** (`locqa/checks.py`). Сами по себе, без LLM, дают 158 находок.
Ниже то, что именно нашли правила в `intl_kk.arb`:

* **Сломанные плейсхолдеры (12):** у плейсхолдера сняты скобки (`Жаңарады: time`), имя искажено
  (`{platformColo}`, `{leve}`), плейсхолдер пропал целиком (`ҰПАЙ` вместо `{points} ОЧКОВ`).
  Два из них ломают сборку `flutter gen-l10n`. Исправления строятся автоматически: скобки
  восстанавливаются, опечатки в имени исправляются по расстоянию Левенштейна.
* **Мусорные «хвосты» у коротких подписей:** «режимін қосу және жалғастыру», «туралы толық ақпарат
  алу үшін», «бөліміне өту үшін басыңыз». Фразы не вписаны в код: правило само находит повторяющиеся
  n-граммы на концах сильно растянутых коротких строк. На казахском файле нашлись ровно эти три
  фразы, на узбекском — ни одной.
* **Строки на чужом языке (16):** узбекский текст (10 строк), португальский (1), английский. Язык
  определяется по скрипту и маркерам и подтверждается точным совпадением со строкой из `--ref`.
  Бренды вроде «MIDAS CREW ЖИНАҒЫ» не помечаются.
* **Русские двойники казахских букв:** `сыйлык`, `жане`, `Кайта`, `тандау` и т.п. Словарь берётся
  из самого файла: форма с ә/ғ/қ/ң/ө/ұ/ү/һ/і встречается в нём N раз. Отдельно ловятся латинские
  гомоглифы (`өтiп`, `көтерілеcің`), русская «и» в казахском суффиксе (`тексеріңиз`, `Мезгілдик`)
  и сломанный регистр (`САғ`).
* **Аффикс вплотную к плейсхолдеру:** `{provider}-ға`, `{max}-нан`, `{fromUser}-дан`. Предлагается
  переформулировка через опорное слово, которое принимает аффикс по своей гармонии:
  `{provider} қызметіне`, `{fromUser} ойыншысынан`.
* **Копии русского текста.** Бренды, числа и список устоявшихся заимствований (Гараж, Бонус…)
  исключаются. Уверенность выше у длинных фраз, у фраз с русскими служебными словами и глаголами
  и в случаях, когда тот же исходник переведён в другом ключе. Из 249 совпадений с русским
  в отчёт попали 21. Остальные — легитимные заимствования.
* **Отсутствующие ключи (12)** и предупреждения уровня файла: 10 ключей определены дважды с
  разными значениями. Dart берёт последнее, это тоже видно в отчёте.
* **Глоссарий:** запрещённые варианты («Отмена» → «БАСТАУ», то есть «Начать»; «скины» → «терілер»,
  то есть «шкуры»; «кирка» → «күрек/шаппа/қайрақ»; «выговор» → «айыптау»).
* **Несогласованные термины:** один и тот же исходник переведён по-разному. Мажоритарный перевод
  не предлагается как исправление, если он сам помечен как ошибка — иначе инструмент тиражировал
  бы «БАСТАУ» вместо «Болдырмау».

**Слой B — LLM-ревьюер.** Весь файл (5467 пар ru/kk + en) прочитали 6 независимых проходов Claude с
инструкцией «только реальные ошибки, тип из таксономии, минимальное исправление». Получилось 363
находки. Их тексты лежат в `work/kk_llm_review.jsonl`, в отчёт они вливаются через `--review`.
Этот слой нужен для `machine_translation_suspect`: ошибки смысла правилами не ловятся. Примеры:
«Брак» → «Заңға бағынушылық» («законопослушность»); «Пистолет» → «Топ» («пушка»);
«Не готов к обмену» → «айырбастауға дайын» (потеряно отрицание); «Железная лига» → «Темір қайла»
(«железная кирка»); «круглосуточно» → «10.00-ден 22.00-ге дейін»; в блоке Twix — «фарш» вместо
«шоколада».

Пересечение слоёв — честная оценка полноты правил. По ключам правила и LLM совпали на 128 ключах.
По типам, которые ловятся правилами (плейсхолдеры, чужой язык, пропуски, копии русского, длина,
аффиксы), LLM независимо подтвердил 128 из 158 ключей, найденных правилами. LLM дополнительно нашёл
около 20 орфографических ошибок, которых нет в словаре файла (`бузған`, `коріп`, `ТЮНГ`), и почти все
смысловые ошибки.

**Слой C — проверка исправлений.** Каждое из 303 предложенных исправлений отдельно оценил
«редактор»: 3 прохода, ни один не видел, как исправление создавалось. Итог: 261 принято,
38 улучшено, 3 найдены ложными (длина «Енгізу үшін басыңыз» на самом деле в норме — после этого
общее правило «… үшін басыңыз» убрано из кода), 1 исправление отклонено (находка осталась без авто-фикса).
Вердикты в `work/kk_verify.jsonl`.

### Порог шума
Каждая находка получает калиброванную `confidence`. В `report.json` попадают находки с confidence ≥ 0.6.
Более слабые не теряются: они лежат в `report.meta.json → candidates_below_threshold` (338 штук)
и открываются в HTML переключателем «show candidates». Так ревьюер может их разобрать, не засоряя
основной отчёт.

### Severity
Severity отражает влияние на игрока, а не уверенность:
* **high** — ломается рантайм или строка нечитаема: плейсхолдеры, плюралы, чужой язык, пропуск,
  длинная копия русского, грубая смысловая ошибка;
* **medium** — неверный термин, аффикс, орфография, заметное переполнение;
* **low** — стилистика и согласованность.

## 3. Как исправляли

1. Приоритет источников исправления: детерминированный ремонт (плейсхолдеры, буквы, хвосты, регистр,
   глоссарий) → перевод того же исходника из других ключей файла (только если он сам не помечен) →
   LLM-исправление → независимая проверка исправления. Массового перевода «всего заново» нет:
   правки затрагивают 315 из 5479 строк (5.7 %), и каждая привязана к конкретной находке.
2. `locqa fix` правит файл точечно: порядок, форматирование и `@@comment` сохраняются.
   Добавленные ключи вставляются на своё место по порядку исходника. У дублирующихся ключей
   правятся все вхождения.
3. У каждой изменённой строки есть отметка:
   `"@key": {"x-locqa": {"reviewed_by_human": …, "reviewer": …, "issue_types": […], "original": …}}`.
   Атрибуты с префиксом `x-` разрешены спецификацией ARB, gen-l10n их игнорирует.
   Флаги продублированы в `intl_kk_fixed.review.json` и `intl_kk_fixed.changes.csv`.
4. `locqa validate` повторяет проверки gen-l10n: валидный JSON, ICU-синтаксис каждой строки,
   плейсхолдеры перевода есть в шаблоне, у plural/select есть `other`. Исходный `intl_kk.arb` даёт
   2 ошибки компиляции, исправленный — 0.
5. Повторный прогон `check` по исправленному файлу: 3 находки вместо 349.

## 4. Проверка носителем (обязательный шаг)

`reviewed_by_human: true` ставится **только** по решениям человека. Автоматическая и LLM-проверка
не считаются человеческой.

**Результат:** носитель казахского (Sayan) прошёл все 316 предложенных правок в `report.html`:
269 принято, 45 исправлено вручную, 2 отклонено как ложные срабатывания (`work/decisions.json`).
В `intl_kk_fixed.arb` изменено 313 строк, и все 313 помечены `reviewed_by_human: true` с именем
проверяющего. Строк без проверки человеком в изменениях нет.

**Контрольная проверка вторым проверяющим.** Из 269 принятых без правок строк мы случайно выбрали 40
(`work/second_review_40.csv`, seed 7). Второй проверяющий подтвердил все 40 («да»), замен не
предложил. Выборка небольшая, это контрольная проверка, а не повторная проверка всего файла.

Процесс для носителя казахского в команде:
1. Открыть `out/report.html`, ввести имя в поле «Reviewer name».
2. Для каждой строки нажать **Accept fix** / **Edit…** / **False positive**. Прогресс сохраняется в
   браузере. Фильтр «Not reviewed» показывает оставшееся.
3. **Export decisions.json** → положить в `work/decisions.json` → `./scripts/run_case.sh`.
   Принятые и отредактированные строки получат `reviewed_by_human: true` и имя ревьюера.
   Ложные срабатывания исчезнут из отчёта.

Ожидаемое время: около 316 ключей × 10–15 с ≈ 1–1.5 часа.

## 5. Стоимость LLM

* Ревью (6 проходов) + проверка исправлений (3 прохода): около 1.08 млн токенов суммарно
  (≈ 0.82 млн + 0.26 млн, по счётчикам выполнения).
* Встроенная команда `locqa llm-review --dry-run` оценивает один полный проход по файлу примерно в
  347 тыс. входных токенов плюс около 15 % выходных. Подставьте актуальные цены модели в
  `--price-in/--price-out` (USD за 1 млн токенов), и команда посчитает стоимость.
  Ответы кэшируются (`.locqa_cache/`), поэтому повторные прогоны бесплатны.
* В CI LLM не используется. Там работают только правила, это 0 ₸ и около 1 с на файл.

## 6. Ограничения (честно)

* Основную проверку (316 строк) выполнил один носитель. Второй проверяющий просмотрел только
  выборку из 40 случайных принятых строк, поэтому согласованность оценок между людьми мы измерили
  лишь на этой выборке, а не на всём файле.
* После исправления остаются 5 находок (`out/recheck_fixed.json`): часть из них ложные срабатывания
  (например, название режима «КАР-РЕГБИ»), остальные требуют решения носителя.
* Список подложенных ошибок нам неизвестен, поэтому полноту мы оценить не можем. По типам:
  находок с подложенными признаками (сломанные `{}`, хвосты, узбекские строки, удалённые ключи,
  двойники букв) правила нашли практически все в своём классе.
* `machine_translation_suspect` (166) — в основном реальные ошибки оригинального перевода, а не
  подложенные. Эти находки зависят от LLM-слоя.
* Тип находки иногда спорен. «Брак» → «Заңға бағынушылық» — это одновременно смысловая ошибка и
  переполнение. Мы оставляем один тип по приоритету: смысл > длина, если длина не вызвана
  мусорным хвостом.
* Транслитерация: «ц», «я», «ю» передаются как `ts`, `ia`, `iu`. Для заимствований стоит свериться
  с орфографическим словарём, когда он выйдет.
